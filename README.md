# Smart Expense Tracker API (app)

A small REST API for tracking personal expenses, built with **Python 3.10+ / FastAPI**.
Expenses are persisted to a local JSON file — no database required.

Everything the brief asks for is covered: add an expense, view all expenses, filter by
category, totals (overall and per category), and delete. The chosen bonus is a
**monthly summary endpoint**. Interactive Swagger docs come for free with FastAPI at
`/docs`.

> There is also an optional demo front end in [`web/`](web/README.md). It is **not** part
> of the deliverable and is not needed to install, run or test the API — the three
> commands below are complete on their own.

---

## Quick start

Requires Python 3.10 or newer. Run these from the repository root:

```bash
# 1. install dependencies
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

# 2. start the server (http://127.0.0.1:8000)
uvicorn src.main:app --reload

# 3. run the tests (in a second terminal, same virtualenv)
pytest
```

`requirements-dev.txt` includes `requirements.txt`, so that single install covers both
running the server and running the tests.

Once the server is up:

* Swagger UI — <http://127.0.0.1:8000/docs>
* ReDoc — <http://127.0.0.1:8000/redoc>
* Health check — <http://127.0.0.1:8000/health>

Data is written to `data/expenses.json` (created on first write, git-ignored). Point it
somewhere else with `EXPENSES_DATA_FILE=/tmp/expenses.json uvicorn src.main:app`.

## API reference

Base URL: `http://127.0.0.1:8000`

| Method   | Path                        | Description                                        |
| -------- | --------------------------- | -------------------------------------------------- |
| `POST`   | `/expenses`                 | Add an expense → `201` with the created record      |
| `GET`    | `/expenses`                 | View all expenses; filter with `?category=&from=&to=` |
| `GET`    | `/expenses/{id}`            | Fetch one expense → `404` if unknown                |
| `PATCH`  | `/expenses/{id}`            | Update selected fields                              |
| `DELETE` | `/expenses/{id}`            | Delete an expense → `204`, or `404` if unknown      |
| `GET`    | `/expenses/totals`          | Overall total + per-category breakdown              |
| `GET`    | `/expenses/summary/monthly` | **Bonus:** spend grouped by calendar month          |
| `GET`    | `/expenses/categories`      | Distinct categories currently in use                |
| `GET`    | `/health`                   | Liveness probe                                      |

### The expense resource

```json
{
  "id": "c3359f69-fd73-4b82-9a38-0a0bba0ef7a2",
  "title": "Lunch",
  "amount": 12.50,
  "category": "food",
  "date": "2026-07-01"
}
```

* `id` — UUID, generated by the server; clients must not supply it.
* `title` — 1–120 characters, non-blank.
* `amount` — a positive number with at most 2 decimal places.
* `category` — free-form, but normalised to trimmed lowercase (`"  Food "` → `"food"`),
  so filtering and grouping are case-insensitive.
* `date` — ISO `YYYY-MM-DD`; defaults to today if omitted.

### Examples

```bash
# add
curl -X POST localhost:8000/expenses \
  -H 'Content-Type: application/json' \
  -d '{"title":"Lunch","amount":12.50,"category":"Food","date":"2026-07-01"}'

# view all / filter by category (case-insensitive) / filter by date range
curl localhost:8000/expenses
curl "localhost:8000/expenses?category=food"
curl "localhost:8000/expenses?from=2026-07-01&to=2026-07-31"

# totals, overall and for a single category
curl localhost:8000/expenses/totals
curl "localhost:8000/expenses/totals?category=food"

# bonus: monthly summary
curl localhost:8000/expenses/summary/monthly

# delete
curl -X DELETE localhost:8000/expenses/<id> -i
```

`GET /expenses/totals` responds with:

```json
{
  "total": 154.75,
  "count": 4,
  "by_category": [
    { "category": "food", "total": 99.75, "count": 2 },
    { "category": "transport", "total": 40.00, "count": 1 },
    { "category": "entertainment", "total": 15.00, "count": 1 }
  ]
}
```

### Status codes

| Code  | When                                                                |
| ----- | ------------------------------------------------------------------- |
| `200` | Successful read or update                                            |
| `201` | Expense created                                                      |
| `204` | Expense deleted (empty body)                                         |
| `400` | Contradictory query, e.g. `from` later than `to`                     |
| `404` | Unknown expense id                                                   |
| `422` | Payload failed validation (negative amount, blank title, bad date …) |

```
│   ├── service.py            # totals / monthly aggregation (pure functions)

│   └── dependencies.py       # repository injection
├── tests/
│   ├── conftest.py           # fixtures: temp-file repo + TestClient

│   └── test_storage.py       # persistence unit tests
└── web/                      # optional demo UI — see web/README.md
```

Four layers, each with one job: routes translate HTTP, models validate, the service does
arithmetic, the repository persists. The route layer depends on the repository through
FastAPI's dependency injection, which is what lets every test run against a throwaway
temp file instead of real data.

## Design decisions

* **Money is `Decimal`, not `float`.** Summing floats drifts (`0.1 + 0.2` → `0.30000000000000004`),
  which is unacceptable for a totals endpoint. Amounts are quantised to 2dp on the way in
  and serialised as JSON numbers on the way out; the JSON file stores them as exact
  decimal strings so a save/load round-trip is lossless. There is a regression test for this.
* **Categories are normalised, not enumerated.** A fixed enum would reject legitimate
  categories; raw strings would split `"Food"` and `"food"` into different buckets.
  Trim + lowercase gets the benefit of both.
* **Writes are atomic.** The store is written to a temp file and `os.replace`d into
  position, so a crash mid-write can't leave a truncated, unloadable JSON file behind.
  A lock guards the read-modify-write cycle, because uvicorn runs sync endpoints on a
  thread pool and requests really can overlap.
* **A corrupt data file fails loudly** at startup rather than silently discarding
  someone's expenses.
* **Route order matters.** `/expenses/totals` is declared before `/expenses/{expense_id}`;
  otherwise FastAPI would match `totals` as an id and always 404.

## Tests

44 tests, run with `pytest`, covering:

* all five required operations, plus the bonus endpoint
* validation rejections — blank title, zero/negative/non-numeric amount, bad date,
  unknown fields
* case-insensitive category filtering and empty-result filtering
* totals on an empty store, totals for one category, and per-category totals summing to
  the overall total
* `404` on reading, updating and deleting an unknown id
* persistence: data survives a simulated restart, deletes are persisted, a corrupt file
  raises
* the decimal-precision regression described above

Tests never touch `data/expenses.json` — each one gets a fresh repository on a `tmp_path`
file injected via `app.dependency_overrides`.
